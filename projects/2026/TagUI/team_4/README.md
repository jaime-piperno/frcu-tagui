## 🤖 Bot Description
- **Description:**
RPA bot that monitors Telegram Web A (`https://web.telegram.org/a/`), detects chats with new messages (unread badge), extracts the last incoming message and sends back an automatic reply generated by a Python module: welcome menu, course details (exact or fuzzy matching), suggestions, farewells or fallback messages.
- **Stage 2 improvement – course enrollment:** users can enroll in a course from the same chat. The bot shows the available seats of each course, asks for full name, ID number (DNI), email and phone (validating each one), shows a summary to confirm (YES/NO) and registers the enrollment as a new row in an Excel spreadsheet. Each course has a seat limit, and the same DNI cannot enroll twice in the same course.
- **Technology used:** TagUI v6.114 + Chrome (CDP integration) + Python 3 + Microsoft Excel

### How the parts work together
- **TagUI** (`src/bot_telegram.tag` and `src/flujos/`) does all the interaction: it reads and sends messages in Telegram Web and is the only part that reads and writes the Excel spreadsheet.
- **Python** (`src/procesar_consulta.py`, `src/preinscripcion.py`, `src/cursos.py`) decides what to reply and keeps track of each enrollment conversation.
- They communicate through files: TagUI writes `entrada.json`, runs Python and reads the reply from `salida.json`. When Python needs the spreadsheet (seats or repeated DNI), it asks TagUI to read it; when the user confirms, it asks TagUI to add the row.

## 🛠️ Usage Instructions
1. **Install prerequisites**: Windows 10/11, Google Chrome, Python 3 (on PATH) and Microsoft Excel. Install TagUI v6.114 in `C:\tagui\` (download v6.110 and run `tagui update`, see the guides below). Java is not needed.
2. **Close Excel** before starting the bot: TagUI controls the Excel application and would use any open instance.
3. **Run the bot** from the project root:
   ```bash
   tagui src\bot_telegram.tag
   ```
   The first time, do not touch the blank Chrome window while TagUI starts. When Telegram Web shows a QR code, scan it from the phone (Telegram → Settings → Devices → Link Desktop Device). The session is kept for the next runs.
4. **Expected output**: for every chat with an unread badge, the bot opens the chat with the *oldest* pending message, reads it and replies. Try `hola`, a course name such as `yoga`, and then `INSCRIBIRME`. After confirming with `SÍ`, the bot minimizes Telegram for a few seconds, shows the spreadsheet `preinscripciones.xlsx` (on the user's Desktop) with the new row, and sends the confirmation with the enrollment number.
5. **Automated tests** (no Telegram or Excel needed):
   ```bash
   python -m unittest discover tests
   ```

## 📝 Additional Notes

- **Configuration:**
  - Seats per course: `cupo` column of `data/cursos.csv` (read on every message, no restart needed).
  - Spreadsheet folder and display: first lines of `src/bot_telegram.tag` (`carpeta_planilla` and `mostrar_planilla_al_registrar`).
- **Files generated while running** (ignored by Git): `bot.log`, `entrada.json`, `salida.json` and `data/sesiones.json` (state of each conversation). They contain the users' data, so they must not be shared.
- **Current limitations of the bot:**
  - Depends on the live DOM of Telegram Web A (CSS selectors may change across versions).
  - Replies to *every* chat with unread messages of the logged-in account: use an account dedicated to the bot.
  - Excel must stay closed while the bot runs; each spreadsheet access takes a few seconds.
  - The spreadsheet is not scrolled: with many rows, the new row may be below the visible area when it is shown.
  - Fuzzy matching thresholds are constants in `src/cursos.py` (0.65 to suggest, 0.75 to infer a course).
